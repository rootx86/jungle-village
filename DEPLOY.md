# Deploying: Cloudflare Pages (website) + one Hetzner VPS (API and database)

About 4 to 6 euros a month. The website is static files on Cloudflare's CDN (free, unlimited bandwidth); the VPS runs only the API and Postgres.

```
viewer's browser --> Cloudflare Pages   (static website, free)
                 \-> api.yourdomain.com --> Cloudflare (proxy, cache) --> Hetzner VPS: Caddy (HTTPS) -> API -> Postgres
```

## Where your secrets go

| Secret / setting | Put it here | Never here |
|---|---|---|
| `ADMIN_TOKEN` (replaces `change-me`) | `/opt/jungle-village/.env` **on the server**, generated by `deploy/make-env.sh` | the repo, the website, chat, URLs |
| `YT_API_KEY` | same server `.env` (the script asks for it with hidden input) | the website, the repo |
| `POSTGRES_PASSWORD` | same server `.env` (generated) | anywhere else |
| `YT_OAUTH_*` (only for owner OAuth mode) | same server `.env` | the repo |
| `NEXT_PUBLIC_API_URL` (e.g. `https://api.example.com`) | Cloudflare Pages build setting. It is public by design, not a secret | n/a |

- The server `.env` is `chmod 600`, owned by root, and listed in `.gitignore` and `.dockerignore`.
- The website bundle contains **no secrets** (only the public API URL).
- Restrict the YouTube key in Google Cloud: API restriction = YouTube Data API v3, plus an IP restriction to your server's IP.
- To rotate anything: `nano /opt/jungle-village/.env`, then `docker compose -f docker-compose.vps.yml up -d`.
- Do not use the `?admin=TOKEN` panel in production (it puts the token in the URL and browser history). Call the admin API with curl instead:
  `curl -X POST https://api.example.com/api/admin/simulate -H "x-admin-token: $(grep ADMIN_TOKEN /opt/jungle-village/.env | cut -d= -f2)" -H "content-type: application/json" -d '{"count":1}'`

## 1. Get a YouTube API key
Google Cloud Console, new project, enable **YouTube Data API v3**, Credentials, **Create API key**, restrict it as above. Your channel id for @OldSchoolStoriesTV is already the default: `UCFZLzGrnth6TDH_Xyh_McBQ`.

## 2. Create the server
1. Hetzner Cloud: new project, **CX22**, Ubuntu 24.04, add your SSH key.
2. DNS: an `A` record `api` pointing at the server IP. With Cloudflare DNS, turn the orange proxy cloud **on** and set SSL/TLS mode to **Full (strict)**. No domain yet? Use `api.<ip-with-dashes>.sslip.io` (for example `api.5-6-7-8.sslip.io`): free, and Caddy gets a real certificate for it (use it without the Cloudflare proxy).

## 3. Install and start (from your PC, in the project folder)
```bash
tar --exclude=node_modules --exclude=.next --exclude=out --exclude=.env --exclude=wip-globe-animals -czf jv.tgz .
scp jv.tgz deploy/setup-vps.sh root@SERVER_IP:/root/
ssh root@SERVER_IP
bash setup-vps.sh                                  # Docker, firewall, swap, automatic security updates
mkdir -p /opt/jungle-village && tar -xzf jv.tgz -C /opt/jungle-village && cd /opt/jungle-village
bash deploy/make-env.sh                            # asks for domain, website origin, channel, API key (hidden); generates ADMIN_TOKEN and DB password
docker compose -f docker-compose.vps.yml up -d --build
curl https://api.example.com/api/health            # {"ok":true}
```
Migrations run automatically on start. The first poll records the channel's current subscribers as the baseline and creates up to `YT_BACKFILL_LIMIT` (15) villagers; after that every new subscriber becomes a villager within `YT_POLL_INTERVAL_SEC` (5 minutes).

## 4. Deploy the website to Cloudflare Pages (free)
Build with your API URL baked in, then upload the `out/` folder:
```powershell
cd frontend
$env:NEXT_OUTPUT='export'; $env:NEXT_PUBLIC_API_URL='https://api.example.com'
npm ci; npm run build
npx wrangler pages deploy out --project-name jungle-village     # or drag the out/ folder into Pages, Direct Upload
```
Or connect the git repo in Pages: root directory `frontend`, build command `npm run build`, output directory `out`, environment variables `NEXT_OUTPUT=export` and `NEXT_PUBLIC_API_URL=https://api.example.com`.

Then tell the API which website may call it: in the server `.env` set `CORS_ORIGIN=https://jungle-village.pages.dev` (your final site URL, comma separated for several) and run `docker compose -f docker-compose.vps.yml up -d`.

## 5. Make the CDN absorb traffic spikes (Cloudflare dashboard, 2 minutes)
Rules, Cache Rules, create rule: *hostname equals `api.example.com` AND URI path is in `/api/village`, `/api/stats`* then **Eligible for cache**, edge TTL **Use cache-control header** (the API sends `s-maxage=20`). A million viewers then cost your server a few requests a minute. New villagers still appear instantly through the live connection (`/api/events`), which is not cached.

## Updating later
Re-run the `tar`/`scp` step, then on the server: `docker compose -f docker-compose.vps.yml up -d --build`. Rebuild and re-upload `out/` only when the frontend changed.

## When you outgrow one server
Move Postgres to Neon or Supabase (change `DATABASE_URL`), run two or more API containers behind a load balancer (the API is stateless apart from the live-connection list, which each instance serves to its own clients), and keep the CDN rules above. The rate limiter is per instance; put Cloudflare rate limiting in front for serious traffic.

## Backups
By your decision there are none: if the volume or server is lost, the village starts again from the channel's current count (new random names and house positions). To change your mind later: `docker compose -f docker-compose.vps.yml exec db pg_dump -U jungle jungle > backup.sql`.
